## Design handoff update — 27 Nov 2026

### Owner direction: user psychology must lead every design

Do not translate references directly into trendy visual clones. For every new concept, first state the target user/context, task, emotional/psychological friction, trust requirement, information hierarchy and intended behavior. Then explore the visual treatment.

Avoid generic AI/fintech imagery (neural spheres, gratuitous glow, meaningless HUD labels, glassmorphism without function). Technical metaphors must map to real product meaning. Retention must come from value, clarity, belonging and progress—not manipulative urgency, shame, notification pressure or arbitrary reward loops.

### Claude implementation / design-review instructions

- Treat references and prototypes as inspiration, not exact visual requirements.
- Preserve broad creative latitude; do not impose a single theme or palette.
- Before implementing, inspect the existing repository and reuse components/assets where appropriate.
- For motion, use feedback/orientation, not perpetual decoration; provide reduced-motion behavior, pause offscreen effects and test mobile performance.
- Do not imply live, verified, secure or AI-certain states unless product data and rules substantiate them.
- Include a short rationale and testable acceptance/review criteria with the artifact.
- Review outcomes: Retain / Refine / Restrict / Remove, based on user benefit and evidence.
