# Users, Screens and Page Flows

## User groups

- Fresher / learner: learn, practise and prepare for first role.
- Experienced engineer: demonstrate depth, grow and discover opportunities.
- Mentor / expert: share knowledge and build contribution reputation.
- Instructor / content owner: publish and review courses and labs.
- Recruiter / HR: find relevant, evidence-backed candidates.
- Admin and SuperAdmin: moderation, review, support, policy and operational control.

## Main product journeys

- Signup and progressive onboarding → role/interests/goals → profile readiness and visibility preview.
- Learning hub → course/resource → practice/lab → assessment → evidence and skill verification.
- Community hub → browse/search → question or article → contribution/answer → reputation and reusable knowledge.
- Career/opportunity discovery → member profile and evidence → recruiter workflow and human review.
- Resource lifecycle → upload, validate, detail/reader, save/share, feedback, moderation, version and attribution.
- Account settings → privacy, visibility, security, recovery and access controls.

## Screen families

Community questions, question detail/answering, resources hub/detail/reader, groups/events/mentoring, learning/practice/assessment, member profile, signup/onboarding/account, recruitment, and role-aware admin/analytics dashboards.

## Nested navigation model

- Route-backed child pages for substantial tasks.
- Drawers/sheets for contextual work; inline expansion for simple details.
- Mobile may use full-screen child flows.
- Preserve parent context, URL and browser history, breadcrumbs/back, query/filter/selection state, scroll position and focus.
- Avoid stacked modal chains and context loss.

## Trust and privacy

Explain what is shared, with whom and why. Avoid exposing CVs, certificates, contact data or employer details without permission. Verification status must be grounded in an evidence record and distinguish community reputation from verified skill.

## Source boundary

The canonical flow document contains screen, workflow and traceability IDs. Validate all proposed flows against the live repository and implementation before declaring them built.
