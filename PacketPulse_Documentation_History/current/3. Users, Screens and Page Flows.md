## 2. Information architecture

### 2.1 Structure

```
Public        Home, Fees, Sign in, Join
Onboarding    Verify email, choose Fresher or Experienced, required details, resume review, consent
Member        Dashboard, Learn, Practice, Assessments, Jobs, Applications, Community (Discover, Questions, Discussions, Knowledge, Resources, Groups, Events, Mentors, Saved), Profile, Notifications, Settings
Reviewers     Reviews (queue, detail), Mentoring, Content (instructors and admins)
Recruiter     Dashboard, Candidates (list, review), Positions (list, detail, form), Interviews
Admin         Operations (Analytical Workspace), Verification, Taxonomy, Content, Payments, Analytics, Moderation, Experiment review
SuperAdmin    Users, Roles, Policies, Security (plus all Admin areas)
```

Relationships that drive navigation: Profile and Taxonomy feed Jobs and Candidates; Assessments, Practice and Verification feed the evidence recruiters see; Jobs feed Applications; Positions feed Candidates; Payments depend on Learn (priced content) and Applications (placement fee); every area writes to the audit log in Operations.

Applying for jobs stays blocked until the required details are complete (PRD-003); every other path opens as soon as the member reaches the dashboard.

### 2.2 Navigation by role

| Role | Primary navigation |
| --- | --- |
| Member | Home, Learn, Practice, Assessments, Jobs, Applications, Community, Profile |
| Mentor | Member pages plus Reviews and Mentoring |
| Instructor | Member pages plus Reviews and Content |
| Recruiter | Dashboard, Candidates, Positions |
| Admin | Operations, Verification, Reviews, Taxonomy, Content, Payments, Analytics |
| SuperAdmin | Admin pages plus Users, Roles, Policies, Security |

Navigation is built from the person's permissions, and the server checks every page and action again (DEC-010). Deep links survive sign-in. A denied page shows a plain explanation and a valid destination (SCR-043). Members have eight items; the mobile bottom bar shows the five most used: Home, Learn, Practice, Community, Jobs, with the rest behind a More item **\[REVIEW\]**.

### 2.3 Visual flexibility across parent/child screens

Child workflows inherit the product's shared design language but are not forced into identical layouts. Explore drawers, sheets, split workspaces, full-page readers, responsive master-detail layouts, contextual tabs and inline expansions based on the task. Use PacketPulse brand motifs as optional transparent overlays; the current pattern work preserves existing page/card backgrounds. Colour, display type and motion can vary by context while navigation, state and accessibility remain coherent.

## 3. Page rules that apply to every screen

| Rule | Detail |
| --- | --- |
| States | Every data screen has loading, empty, error, success and, where relevant, disabled states (DES-001) |
| One primary action | At most one primary button per screen or dialog (DES-008) |
| Titles | One H1 per page; the browser tab title follows it |
| Back and deep links | Detail pages show a breadcrumb; filters and scroll position are kept when returning to a list |
| Responsive | One column below 768 px; tables become stacked cards; dialogs become full screens for long tasks |
| Keyboard | Everything reachable; focus moves to the page heading after navigation |
| Unsaved work | A warning before leaving a changed form; long forms save and resume |
| Permissions | A person never sees a control they cannot use; the server rejects it anyway |

### 3.1 Workspace layout families

| Workspace | Screens | Composition |
| --- | --- | --- |
| Editorial Workspace | Member dashboard, Community discovery, thread, article, learning and profile | Reading-led hierarchy, generous whitespace, contextual navigation, narrow reading measure where appropriate |
| Analytical Workspace | Operations, recruiter analytics, admin analytics, moderation and verification queues | Grouped sidebar, breadcrumb/header, context filters, 4–5 KPIs, primary chart/table area, collapsible contextual rail and detailed records |

The supplied Vantage Admin screenshot is an inspiration reference for the Analytical Workspace, not a pixel-perfect implementation target. Use Matte Black Edition tokens for the preferred analytics reference; support the light theme and responsive layouts. Community/learning editorial pages should not be forced into a dense admin-dashboard pattern.

### 5.1 Resource and identity screen specifications (review build)

**SCR-054 — Resources Library**
- Header: breadcrumb Community / Resources, H1 “Resources”, one-line purpose statement, primary “Share a resource” action.
- Discovery feature: optional featured collection with editorial illustration/diagram, title, short description and CTA.
- Tabs: For you, Featured, Recent, Popular, Staff Picks. Filters: Category, Format, Technology, Difficulty, Audience, Sort.
- Main content: resource cards with file/type icon or thumbnail, title, short value proposition, technology chips, author/source, difficulty/estimated time, updated/reviewed date, save control and moderation/quality label where applicable.
- Optional right rail: popular topics, recently added, curated collections and “continue reading”; collapses on tablet and becomes a sheet/stack on mobile.
- States: first-use empty, no results, loading, error/retry, saved, hidden/removed resource and restricted resource.

**SCR-055 — Resource Detail / Reader**
- Primary column: document/media/article preview with zoom/page controls where supported; article uses readable measure and section anchors; video has captions/transcript when available; external links show destination before opening.
- Secondary rail: table of contents, metadata, format, difficulty, estimated time, version, last reviewed, author/contributor, source, licence and attribution.
- Actions: Open/Download (when permitted), Save, Add to collection, Share, Report issue, Helpful/Not helpful.
- Lower section: related resources, community discussion/questions and “learn/practice this topic” cross-links.
- Do not claim a third-party resource is reviewed unless a real review event exists. Broken or expired links show an explanation and report action.

**SCR-056 — Share a Resource**
- Step 1 Details: title, short description, resource type (Guide, Documentation, Tool, Template, Course, Video, Cheat sheet, Lab, Repository, Article), category, technology tags, difficulty, intended audience and language.
- Step 2 Content: choose Upload file, Paste URL or Write article. Upload supports queued/uploading/paused/processing-scanning/complete/failed/canceled/rejected states. Pause/resume only when transport supports it. Show actual bytes transferred, filename, size and validation.
- Step 3 Review & publish: preview, source/author, attribution, licence/usage rights, optional version and review date, audience visibility, community guidelines confirmation and submission status.
- Save draft at every step. If upload or validation fails, preserve completed fields and offer retry/remove/replace. Never publish a file that has not passed the configured scan and server-side validation.

**SCR-057 — Saved Resources**
- Tabs: All saved, Reading list, My collections, Recently viewed.
- Collection cards show name, description, resource count, privacy/sharing state, cover thumbnail and last updated. Resource list shows type, title, category, reading state, saved date and actions.
- Reading state: Not started, In progress, Completed. Progress is only shown when the underlying resource supports meaningful progress; otherwise use simple saved status.
- Continue reading resumes at a stored, permission-checked location. Member can remove a save without deleting the source resource.

**SCR-058 — Resource Review Queue**
- Analytical Workspace: KPI strip (Pending review, Needs changes, Scan/link issues, Recently published); filters; submission table; contextual review rail.
- Detail pane: content preview, metadata, attribution/licence evidence, file scan, URL health and revision history.
- Actions: Approve, Request changes, Reject, Hide/Archive. Every non-approval action needs a reason; every decision is audited and author receives a status message.

**SCR-003 — Signup and verification refresh**
- Wide screen: split layout with a restrained PacketPulse brand/story panel and a focused account form. Small screens: single-column form with no decorative panel competing with inputs.
- Options: email/password or passkey; Google/GitHub provider buttons are approved for prototype display and interaction. Real provider authentication is enabled only after provider setup and security audit; otherwise show a clearly labelled demo/disabled state in prototype.
- Include password visibility, strength guidance, Terms and Privacy consent, email verification, resend cooldown, error and recovery states. Keep login and account recovery links visible.

**SCR-059 — Personalised onboarding**
- Three-step progression: Role, Interests, Goals. Selected chips/cards show a check and accessible selected state. Role is single-select; interest and goal can be multi-select. Optional fields can be skipped. A small “You can change this later” note reduces pressure.
- On completion, create editable preferences and route to a personalised Community/Resource/Learn landing. Recommendations must be explainable and hide/mute controls are available later.

**SCR-012 — Professional Profile**
- Identity hero: avatar, name, headline, location/timezone if supplied, short introduction, edit button and distinct verification label. Do not use one generic “Verified” badge for every verification type.
- Tabs/sections: Overview, Skills, Experience, Education & Certifications, Contributions, Learning, Mentoring, Activity and Achievements where data exists.
- Skills section groups Self-declared, Assessment verified, Experience verified, Certification verified and PP verified; each has a detail view showing evidence/issuer/reviewer/date/expiry as permitted.
- Contributions show solved questions, useful answers, articles, case studies and mentoring, but community reputation never substitutes for skill verification.

**SCR-060 — Profile visibility preview**
- Preview modes: “My view”, “Community member view” and “Recruiter after forwarding”. The preview is generated by the same field-level policy as actual access; it is not a cosmetic mock.
- Explain each hidden field with a short reason and an action to change the setting when allowed. Do not expose date of birth, compensation, private notes, contact data or resume links beyond DEC-015 and consent.

**SCR-061 to SCR-063 — Account Control Centre**
- Settings hub uses spacious grouped cards: Personal information, Profile visibility, Notifications, Login & security, Sessions, Connected accounts, Privacy & data rights and Billing (when applicable).
- Security/session screens show current device, last active, approximate location only if the auth provider provides it reliably, sign-out controls, MFA/passkey state and recent security events. Do not invent device details.
- Connected accounts explain provider scopes and consequences. Prevent unlinking the last viable recovery method. Account linking/unlinking requires clear confirmation and may require step-up.
- Privacy/data rights reuse SCR-038: view consent, withdraw optional consent, request export, request erasure and see request status. Deletion is separated in a danger zone and requires re-authentication and confirmation of consequences.

## 9. Media, embedded files and parent-child screen behaviour

### SCR-064 — Recording / Media Viewer

**Layout:** Parent resource header and breadcrumbs; primary player; optional transcript/chapter side panel; below/adjacent metadata, captions, notes, discussion and related resources. Audio-only assets may show an optional waveform timeline and region markers. On narrow screens the player remains the primary content and chapters/transcript become tabs or bottom sheets.

**Controls/states:** play/pause, seek, volume, speed, quality where available, captions, transcript, chapters, fullscreen, PiP where supported, source/provider, resume, playback error, network recovery, restricted access, unavailable provider and unsupported codec. Audio waveform, regions and timestamp markers are optional enhancements and should fail back gracefully to familiar audio controls. Keyboard controls and visible focus are essential. No autoplay with sound.

**Recording cards:** show title, thumbnail, duration, source label, caption/transcript indicators, progress and last-viewed state. Keep decorative patterns outside text and control surfaces.

### SCR-065 — Embedded File Preview

Choose a viewer by validated file type: PDF viewer; optimized image viewer; audio/video player; syntax-highlighted text/code/Markdown; virtualized CSV/table preview; supported Office preview via isolated conversion or approved editor. For unknown, unsupported or blocked formats show a clear explanation, safe download when authorised, and report/retry path. Never render raw HTML or macros.

### SCR-066 — Upload Manager / Processing Detail

Support multi-file selection, drag/drop, per-file queue, aggregate progress, pause/resume/retry/cancel, remove/replace, network interruption, duplicate warning, size/type errors, scanning, thumbnail generation, transcoding, moderation and publication. Use real server progress/status. If a prototype uses mock media processing, label it visibly as a prototype state.

### SCR-067 — Media Embed and Source Details

Show original source/provider, resource owner, licence/attribution, embed provider, caption/transcript availability, provider playback status and a report-broken-source control. Provider errors should not break the parent resource page.

### Nested-screen composition guidance

- **Parent page:** establishes section context, filters, selected record and primary task.
- **Child route:** use for substantial workflows, deep links, browser history and pages with their own meaningful state.
- **Contextual drawer/sheet:** use for quick inspection, editing a small set of fields or reviewing details without losing the parent workspace. A route-backed drawer may be used when the detail must be shareable.
- **Inline expansion:** use for small supplementary detail, not large forms or complex media readers.
- **Mobile:** convert complex child panes into full-screen routes or clearly titled sheets with a visible back/close action.
- **State restoration:** keep search, filters, sort, selected parent record and scroll position where feasible. Restore keyboard focus to the invoking control.
- **Avoid:** modal-on-modal, hidden hierarchy, changing the parent background as a navigation cue, and controls that open a child surface without announcing its title.
